## 顶层字段

| 字段 | 含义 |
|---|---|
| `$schema` / `schema_version` | 字段规范的位置 / 数据格式版本，目前为 `1` |
| `id` | 整个谜题的稳定 ID；新谜题必须另取名字，避免与旧谜题共用浏览器进度 |
| `title` / `artist` | 谜题名 / 歌手，中英文各一份 |
| `date` / `restored` | 原作日期 / 复原日期；新作可省略 `restored` |
| `source` | 原始来源网址，新作可省略 |
| `start` / `ending` | 起点 / 唯一终点的节点 ID |
| `map` | 地图坐标系宽、高，`position` 使用该坐标系 |
| `nodes` | 所有歌曲节点；数组顺序决定未发现节点的序号，不决定游玩路线 |

## 每首歌的字段

| 字段 | 含义 |
|---|---|
| `id` | 稳定标识，与歌名分开 |
| `title` | 页面显示的歌名，也是一种可接受答案 |
| `aliases` | 同一首歌的其他可接受写法，如繁体歌名；无别名时为 `[]` |
| `clue.zh` / `clue.en` | 停在这首歌时看到的谜面，指向 `next` 中的下一首或几首歌 |
| `hint.zh` / `hint.en` | 用户主动打开的辅助提示 |
| `next` | 下一首歌曲的 ID 数组；有多个 ID 即分岔，`[]` 表示没有图内后继 |
| `dead_ends` | 可选：当前没有下一条谜面的支线答案，可包含简繁体写法；这些答案不增加歌曲节点。原作意图未逐项确认时，不将它冒称为已核实的原版死胡同 |
| `open_answers` | 可选：作者确认可接但后续暂空的答案，保存 `title`、`aliases`、`clue: null`、`next: null` 和 `review`；接受答案并说明暂空，不新增完整谜面节点 |
| `decoys` | 可选：玩家很可能输入、但不是这条线答案的歌（同曲异词的孪生歌、更有名的同题歌、线索里撞上的歌名），每项 `title`、`aliases`、双语 `message` 和不进页面的 `note`（为什么列为诱饵）。命中时显示 `message`，不算答对、不计入提示催促、输入框不晃；校验器拒绝与本节点任何可接答案或当前歌重名的诱饵。2026-10-04 作者同意孪生歌只提示、不算对 |
| `route_audit` | 可选：路径复核说明、作者确认的新增连接与待核候选；候选不参加答案判断 |
| `position` | 地图中的 `[x, y]` |
| `identity` | 歌名查证依据、候选和人工确认记录 |
| `source` | 可选：豆列 item、虾米原地址及历史前驱记录 |

`next` 是当前图内路径的唯一可编辑定义。`source.predecessors` 是原始材料的证据，使用 `{id, title, url}` 对象保存；其中的历史歌名不随当前 `title` 自动改写。**原评论里的前驱不是全量答案，可能遗漏回环和站外分支，不能要求图内路径与它完全相等。** 作者确认新增的连接同时在 `route_audit.confirmed_additions` 记录 `target`、`by`、`date`、`note`，保留旧来源不改写。前驱关系可以由 `next` 反向推导，不需要再维护一份当前前驱表。

答案判断会忽略大小写、空格、常用标点与书名号；简繁体、译名等词形差异应明确写进 `aliases`，不做猜测式转换。

## 查证依据与人工确认

两层分开保存：作者确认一个推断，并不等于找到了原歌曲页。确认后保留原来的 `evidence_type`、`candidates` 和来源证据。

| `identity.evidence_type` | 含义 |
|---|---|
| `author` | 新谜题由作者直接指定 |
| `cross-reference` | 原始评论中的其他歌名提供交叉证据 |
| `archive` | 已实际打开存档歌曲页核对标题，链接见 `evidence_urls` |
| `contextual-alias` | 根据前后歌曲及谜意对应不同地址，属于上下文推断 |
| `provisional` | 暂定候选，缺少独立身份依据 |

| `identity.review.status` | 含义 |
|---|---|
| `not-requested` | 尚未要求人工确认；不代表作者已认可，也不抹去已有查证依据 |
| `pending` | 已提出具体待确认问题 |
| `confirmed` | 确认了当前候选 |
| `corrected` | 人工改正了候选，原因写在 `review.note` |

`identity.note` 记录查证说明；`identity.candidates` 保存 `{title, reason}` 候选；`identity.review` 记录 `{status, by, date, note}` 人工决定。仅凭收到了文件或改了排版，不会自动变更确认状态。

## 修改、扩展和新建

- **修改歌名或答案**：改 `title` / `aliases`，保留 ID，补确认记录。
- **修改谜面**：改对应 `clue` / `hint` 的中英文。歌词引用和页面改编仍按现有内容规范处理。
- **增加歌曲**：增加唯一 ID 的完整节点，至少让一个已有节点的 `next` 指向它；更新地图位置和必要的线索。原版复原与主动扩展的区别应在来源说明中写清楚。
- **补齐暂空分支**：拿到作者提供的后续谜面后，把对应 `open_answers` 项改为完整歌曲节点，再将其稳定 ID 加入 `next`，移除原占位答案，避免一首歌同时走两种判断。未提供谜面前，保持 `clue` 和 `next` 为 `null`。
- **新建谜题**：复制模板，替换顶层 `id`、歌手、标题、日期及歌曲节点。模板通过同一校验器；回响的专用页面介绍、封面设计、页面地址和 Work 入口仍需要另行配置，复制 JSON 不会自动发布新页面。
- **同步**：直接交回修改后的 JSON，或告知「节点 ID + 字段 + 新值」。JSON 不支持注释，把说明写入相应的 `note` 字段。只维护 JSON 一种格式，避免与 YAML 双份漂移。

## 校验

在仓库目录运行：

```sh
python3 scripts/music_riddle_data.py
python3 scripts/music_riddle_data.py docs/templates/music-riddle.json
```

校验器会报告重复 ID、失效路径、不可达歌曲、分支答案冲突、坐标越界、缺失双语字段、不完整确认记录等，并列出待确认项。结构通过与歌名确认是两件事；存在 `pending` 仍可制作预览。页面构建也会执行这些检查。

当前回响数据没有待确认歌名；以后新加的不确定项使用 `pending` 单独记录。

## 歌词引用与花朵 / 和弦（2026-10-03）

整段谜面来自歌词时，设 `clue_format: "quote"`。原文和译文仍只维护在 `clue.zh/en`，页面使用同一大字号 `blockquote`，不会重复显示正文。省略或 `"prose"` 表示普通谜面。中文引用按逗号分行，英文译文自然换行。`quote` 继续用于《绵绵》这样的独立引文，随后仍可有普通说明；不要同时设置独立 `quote` 和 `clue_format: "quote"`。

每个节点的 `presentation` 现在都经过单独选择，与节点顺序无关。地图、线索面板、已找到的歌共用同一个花朵字段，播放也直接读取同一个节点的和弦。

```json
"presentation": {
  "flower": "blue",
  "flower_reason": "蓝色簇花作为夜间入口，也与倒带的回环相认。",
  "chord": {
    "name": "Csus2",
    "midi": [48, 55, 62],
    "reason": "省去三音的开放悬置，先提出一个问题，留给终点回答。"
  }
}
```

- `flower`：`poppy`（朱红罂粟形）、`blue`（蓝色簇花）、`ivory`（乳白花）、`dahlia`（橙色大丽花）。沿用封面风格的四张生成素材；按形状、色彩和歌曲意象选择，不声明植物花语。
- `flower_reason`：该节点选择此花的理由。
- `chord.name`：便于人工沟通的和弦名称；`midi` 才是实际播放的配器。改名不会自动改音符。
- `chord.midi`：3–6 个互不重复、由低到高的 MIDI 音高，范围 48–72（C3–C5，C4 = 60）。点击节点时**整组同时发声，不是琶音或依次弹奏**；路径回放与终章里，和弦可以按各自的 `roll` 极轻微地摊开（见下）。`(no5)` 表示实际配器省略五音。
- `chord.reason`：和声选择的情绪或路径依据。这里是独立创作的页面提示音，不是对原曲调性或和弦的转录。

声音继续使用 Vocal Coach 同源的 YDP 钢琴采样。所有组成音加载成功后，以同一个音频时钟时间起音；按音数调整单音增益。点击另一节点会淡出上一和弦，静音、重置、切走页面会取消仍在加载的整组声音。

入口与《倒带人生》使用同一 Csus2，回环时重现入口声音；终点《贝多芬与我》是 C 大三和弦的开放排列，《完》的 G7 接它，成为终止式；隐藏尾声（Cmaj7#11）在更高音区回应终点。其余节点用九和弦、十一和弦、挂留、减七、mMaj9 等扩展和弦，相邻歌曲之间的声部移动尽量平滑，也避免连续重复同一种色彩（37 个和弦有 35 种写法，以 4–5 个音为主）。完整选择及理由仅维护在 JSON 中。

旧 v1 数据可以省略 `presentation`，使用固定蓝花与 Csus2；新模板明确写出示例。校验器检查花朵标识、理由、和弦音数（3–6）、音域、排序和重复音。

## 路径回放与终章（2026-10-03）

两种"乐曲"都直接读取上面的节点和弦，不引入新的音频文件。时间、力度与路径逻辑在 `src/ts/echo-score.ts`（纯函数，没有 DOM 和音频，Node 可测）；排队、动态和取消在 `EchoPiano.Player.playScore`。

**回响这条路。** 当前歌曲下方的"回响这条路"把"从起点到当前歌曲"的路径奏成一段和弦。路径取玩家**实际走通的边**，从当前歌曲往回追溯，每首歌取最近一次走进它的那条边（2026-10-04 起；之前取最短的一条，同长时取先走的，会回放旧路），不是点击顺序，也不使用没走过的边；到隐藏尾声时沿终点接上。匀速（每个和弦 0.7 秒），力度从 mezzo 渐强，最后两个和弦略微放慢，停在你所在的歌曲上并延长。还在起点（只有一首歌）时不显示；最长的一条（到《完》）13 首，约 13 秒。

**终章。** 集齐 36 首、隐藏回响出现约 2.9 秒后（让最后一个和弦和点亮动画先结束）自动奏响一首编排好的曲子：地图变暗，节点随各自的和弦变亮、再随衰减变暗，聚光灯和键盘跟着走；沿图的边相邻的两步还会点亮那条路。最后的隐藏回响响起时，它循环发光三次，其余节点和路错拍闪烁，随后回到暗场；曲终全图亮起。之后可在地图上方的"播放终章"重听；停止用同一个按钮、Esc、静音、切走页面、点击任何歌曲、答对一题或重置。重新载入已集齐的存档不会自动播放。手机上终章打开完整地图弹层，关闭弹层即停止。终章播放期间页面会请求屏幕常亮（Screen Wake Lock），免得手机自动锁屏在乐句中途切断声音；终章结束或被停止时放开，浏览器不支持或拒绝时终章照常播放，路径回放不请求。编排保存在顶层 `finale`：

```json
"finale": {
  "beat": 0.5,
  "steps": [
    {"node": "VbpP7694d", "beats": 4, "level": 0.34, "roll": 0.24},
    {"node": "b8OSHbf0e1", "beats": 2, "level": 0.38, "roll": 0.18},
    {"node": "allegro", "beats": 6, "level": 0.42, "roll": 0.3, "release": 4.5}
  ]
}
```

- `beat`：一拍的秒数（0.25–1.5）。`steps` 共 2–128 步，总长不超过 120 秒。
- `node`：这一步弹哪个节点的和弦，同时点亮它；同一节点可以出现多次，顺序不必沿图的边。
- `beats`：这一步到下一步的拍数（0.25–16）。`level`：力度（0.1–1）。`roll`：把和弦从低到高摊开所用的秒数（0–0.6，缺省为同时发声）。`shape`：把和弦写成分解和弦（可选，2026-10-04 起），音落在节拍格上，每隔 `every` 拍进一个音（0.125–1，缺省 0.5 即八分音符，0.25 为十六分）；有 `shape` 时不看 `roll`。`up` 由低到高；`down` 由高到低；`bass` 低音在拍上，下一格起其余音以一半间隔上行，像左手接右手；`skip` 低音、最高音，再由低到高补中间的音。每个音只弹一次，最后一个音必须在和弦结束前进入。`release`：这一步的衰减时长（0.2–6，缺省 0.6）；最后一步用它做长尾。`gate`：和弦在这一步里实际发声的比例（0.2–1，缺省 0.92，接近连奏）；短的 gate 是断奏的「戳」，给下一个和弦前留出空隙（2026-10-04 起，配合长短交替的摇摆节奏）。
- 校验器要求：最后一步是隐藏尾声，倒数第二步是终点；没有隐藏尾声的谜题则以终点收尾。"每首歌至少出现一次"由测试保证而不是校验器，方便以后删减。
- 现有编排共 38 步、约 46 秒：从入口 Csus2 轻声开始，大体沿图的边前进并经过全部 37 个节点，中途在《倒带人生》回到开场的声音（它与入口同一和弦）；一路渐强到《喜帖街》的 G9sus4，转入《红玫瑰》《黑择明》的暗色，经《完》的 G7 解决到终点的 C，最后隐藏尾声以最轻的力度收尾。

## 测量边界

- Codex 内置 Chromium；390 × 844；CPU 4 倍减速；下载 204,800 B/s、上传 96,000 B/s、延迟 150 ms；禁用缓存。
- 使用现有 `localhost:5199` 静态服务器。它返回未压缩文件，不能代表 GitHub Pages 的传输体积或真实用户体验。
- `PerformanceObserver` 的 buffered 条目用于 FCP、LCP、长任务和布局位移；CLS 取最大会话窗口（间隔小于 1 秒、总长最多 5 秒），排除近期用户输入。不是 Lighthouse 分数，也不是线上 Core Web Vitals 达标证明。
- 通常在导航约 12 秒后读取。阻塞页面使读取推迟；每条原始记录有实际 `at` 和 `ready`。睡眠基线在约 19.4 秒仍处于 loading，最终 DCL 45.7 秒、load 46.7 秒、36 张图；优化后的采样约 16.7 秒，正文 FCP 3.18 秒，原先 16.62 秒。该单次对比只用于定位阻塞，不能当作稳定提速倍数。
- 首页 FCP / LCP 没有在每次采样中都变快，作品页最后一轮 LCP 仍约 5.88 秒。字体和依赖延后减少了明确开销，但不能声称所有页面达到理想加载速度。
- 资源记录的 encodedBodySize 不包含 HTML；部分跨域资源因 Resource Timing 权限返回 0。不得把资源字节总和当作完整网络账单。
- `before.json` 的 exploratory 部分是前期非固定时点样本，位移累加值单独标记为 `unvalidated_layout_shift_sum`，不作为 CLS 对照。正式比较使用 `runs.json` 的 before / audit 与 after / final / priority 样本。
